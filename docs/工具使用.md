# 使用独立工具

## 修复候选（不覆盖输入）

先运行根目录README中的安装和测试，然后设置PYTHONPATH指向python。以下代码可在自己的脚本中使用：

```python
from pathlib import Path
import numpy as np
from desktop.white_mesh_io import iter_exported_points
from desktop.repair_core import apply_operation

# 只支持解析器明确接受的二进制小端XYZ PLY或binary XYZ PCD，并非所有PLY变体。
source = Path('input.ply')
points = np.concatenate(list(iter_exported_points(source)))
result = apply_operation(points, 'radius', {'radius': 0.10, 'min_neighbors': 3})
print(result.stats)
# points与输入保持行对应；去除点通过keep掩码表达，不会提前压缩。
retained = result.points[result.keep]
candidate = np.concatenate((retained, result.added))
# moved表示原行移动情况；added是另外生成的推断点，不能标成实测点。
# 此例不自动覆盖源文件，请自行复检后另存。
```

本例把输入集中到内存，适用于可容纳的数据量。大地图不能仅靠调大阈值解决内存问题；原完整应用的分块编辑/会话存储没有在此子集发布。
地面识别、调平、局部平整、补洞应分步保留候选并做局部复核；它们不能纠正没有轨迹约束的全局SLAM漂移。

## 白模与点云密度

`white_mesh_core.build_mesh_from_points(points, step_m)` 构造局部三角面；`white_building.build_building(points, step_m)`尝试有支持点的建筑结构面。返回布局见函数体与测试，结果交white_mesh_io.export_model另存。
Java WhiteMesh是体素外露面，Python建筑面和体素壳不是同一种建模算法。

减小体素/构面间距可能大幅增加内存、面数和耗时；它不创造新的测量信息。补洞/结构面需要标明推断。空区域、不支持的文件格式、超出预算和用户取消都应作为明确状态处理，不发布残缺结果覆盖原图。

## 收包与运动预览

`decode_packet`可单独解析bytes数据，详见合成报文测试。`Receiver`会实际打开传入的本机UDP端口；运行前核对接口、源地址过滤、端口和是否已有接收程序占用，结束时调用close释放。
这里没有一键连接/启动采样按钮，没有完整手机网络层、系统eth0配置或USB授权界面。纯Java UsbFrames只处理字节数组，并不会自己驱动网卡。

## GPU边界

repair_compute中的OpenCL接口适用于其列出的点计算操作，需要兼容的系统驱动；不是GPU FAST-LIO，也不是手机NPU加速。没有OpenCL时CPU修复仍可运行。本次公开包验收不依赖GPU，不以CPU测试通过宣称GPU驱动适配通过。
